Release Process
Versioning
We use Semantic Versioning:

MAJOR: Incompatible changes
MINOR: New backward-compatible features
PATCH: Bug fixes

Release Steps

Prepare changes
Update CHANGELOG.md
Ensure all tests pass
Update version in package.json

Create a Release
Go to GitHub → Releases → “Draft a new release”
Tag version (e.g. v1.0.0)
Write release notes (summary of changes)
Publish the release

After Release
Announce on GitHub Discussions or website if major
Update documentation if needed


Who can release?
Only Jon Penneman (Project Lead) or designated maintainers.
Frequency
Releases will be made as needed (bug fixes promptly, new features on a reasonable cadence).
